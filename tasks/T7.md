## B15 — CurseForge client tests

Read `internal/provider/curseforge/curseforge.go` fully first — every
endpoint it calls, every header it sets, every error it returns.

- The API key is sent on every request (header, exact form the client uses).
- A non-2xx response (403, 404, 500) returns a Go error that names the
  project/mod, not a bare status code — assert the message is actionable.
- Malformed JSON and empty bodies are errors, not panics and not silent
  zero values.
- Rate-limit (429) handling: whatever the client does (retry, back off,
  return), pin the behaviour in a test so a future change is deliberate.
- The search/id-lookup mapping: a stub response with two files picks the
  right one by the client's own rules (game version, loader).

## B16 — `mrpack` install failure paths

Read `internal/mrpack/install.go` fully first, especially `downloadInto`
(the temp-file-then-rename contract) and whatever verifies hashes.

- Checksum mismatch: `Install` returns an error AND leaves nothing at the
  destination path — no partial jar, no zero-byte file. Assert absence,
  not just the error.
- Truncated download (server closes mid-body / Content-Length lies):
  error, and again nothing usable at dest.
- A pack listing the same file twice downloads it once (the `present` map)
  — pin this, since double-download of a 50 MB jar is user-visible.
- Existing-file skip: a jar already on disk with matching sha1 is not
  re-downloaded (assert via the stub's request count, not just the return
  value).
