# Task T3 — test harness for `internal/cli` (B14)

## Context

`internal/cli` reports 0% coverage. That is how four shipped defects survived:
`add --dry-run` did not dry-run, `add`/`remove` ignored `-i`, `update --all`
reported the wrong run, and the README documented a flag that does not exist.

Task T1 fixes those bugs. This task builds the harness that would have caught
them, so the fixes cannot regress.

Work in a git worktree branched from `main` **after T1 has been merged**:

```
git worktree add ../modharbor-t3 -b test/cli-harness main
```

## Rules

- Only touch `internal/cli/**`.
- No new dependencies. `net/http/httptest` and `os` are sufficient.
- Tests must never touch a real Minecraft directory, the real network, or the
  user's config/state. Point `MODHARBOR_MINECRAFT_DIR` at a `t.TempDir()` and
  set `MODHARBOR_CONFIG_DIR` / `MODHARBOR_DATA_DIR` to temp paths.
- Note that the code reads `XDG_CONFIG_HOME` and `XDG_DATA_HOME` via
  `config.DefaultPaths`; `t.Setenv` both to temp dirs so a developer's real
  `state.json` is never read or written.
- Because `ui` writes to `os.Stdout`, capture it where output matters using
  `ui.SetWriters(buf, buf)`.

## What to cover

Pure helpers, table-driven, cheap and high value:

- `splitArgs` — positional instance, `-i` fallback, both at once, none
- `pickInstanceArg` — args beat flag, flag used when args empty
- `matchMods` — by display name, mod id, project id, exact file name, prefix,
  ambiguity, no match
- `loaderName` and `loaderLabel` for every `instance.Type`
- `projectKey` — bare slug, modrinth.com URL, project URL, trailing slash,
  query string
- `truncateName`, `orDash`, `totalSize`
- `human` helpers in `internal/ui`: `HumanBytes` boundaries, `HumanCount`
  separators, `HumanDuration`
- `visibleWidth`/`Truncate`/`Pad` in `internal/ui` must ignore ANSI escapes,
  which is easy to get wrong and hard to see

Then a small number of command-level tests using an `httptest` Modrinth stub
and a temp instance:

- `list --json` parses and reports counts
- `outdated --json` distinguishes `replace` from `reinstall` from `skip`
- `doctor --json` reports a duplicate as an error-severity finding
- a command pointed at a nonexistent instance exits non-zero **and writes a
  message to stderr**. This is the regression test for the swallowed-error
  bug (B1) and the most valuable test in this file.

## Deliverable

Commit on the branch, then report: the commit hash, the test names, coverage
for `internal/cli` before and after (`go test -cover ./internal/cli/`), and
the verification output. Target a meaningful jump, not 100%; spend the effort
on the helpers and the error-path test rather than on rendering.
