# Task T2 — `watch` mode (B8)

## Context

modharbor answers "is anything out of date?" on demand. People maintaining a
modpack want to know when a release drops without remembering to ask.

Work in a git worktree branched from `main`:

```
git worktree add ../modharbor-t2 -b feat/watch main
```

## Rules

- Only create `internal/cli/watch.go` and register the command in
  `internal/cli/root.go`. You may add `internal/cli/watch_test.go`.
- No new dependencies. Use `context`, `time`, `os/signal` and the existing
  `internal/ui` helpers.
- Follow the style of `internal/cli/outdated.go` for resolving an instance
  and `internal/cli/list.go` for rendering a table.

## Behaviour

`modharbor watch [instance] --every <duration>`

- Default interval: 30m. Accept Go duration syntax (`90s`, `15m`, `2h`).
- Enforce a sensible minimum (60s) so a mistyped `--every 1s` cannot hammer
  the Modrinth API. Reject shorter values with a clear message rather than
  silently clamping.
- Each cycle: resolve the instance, run the same planning pass `outdated`
  uses, and print only when the set of available updates differs from the
  previous cycle. Print nothing when unchanged, so the output stays quiet.
- On a change, render the same table as `outdated` so the output is familiar.
- Use the existing `ui.NewSpinner` while a cycle runs and clear it before
  printing.
- Stop cleanly on SIGINT/SIGTERM: use `signal.NotifyContext`, print a short
  farewell, exit 0. Also honour the caller's context so tests can cancel.
- `--json`: emit one JSON object per cycle on stdout instead of the table, so
  the mode is scriptable.
- `--channel` comes from the global flags; do not add a local one.
- Honour `--offline`: in offline mode refuse to start, since polling without
  network calls would spin uselessly.
- On the first cycle, print the current state rather than treating everything
  as a change, so `watch` starts from a known baseline.

## Testing

Use a stub HTTP server, not the live API.

- The cycle loop honours context cancellation promptly.
- An unchanged second cycle produces no output.
- A changed second cycle produces output.
- `--every 1s` is rejected.
- `--offline` refuses to start.

## Deliverable

Commit on the branch, then report: the commit hash, files changed, test names,
verification output, and a short transcript of a two-cycle run against the
stub showing the "no change" path staying silent.
