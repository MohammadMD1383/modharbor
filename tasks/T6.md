# Task T6 — prove the release pipeline works before tagging v0.1.0 (B17)

## Context

The repo is public but has no tagged release, so
`go install …/cmd/modharbor@latest` does not work yet. `.goreleaser.yaml`
exists but has only ever been validated as YAML, never against the goreleaser
schema, and CI never runs it. Tagging `v0.1.0` fires
`.github/workflows/release.yml`; this task makes sure that works *before*
anyone pulls the trigger.

Work in a git worktree branched from `main`:

```
git worktree add ../modharbor-t6 -b chore/release-check main
```

## Rules

- You may touch `.goreleaser.yaml`, `.github/workflows/**`, `.gitignore`,
  `CHANGELOG.md` (Unreleased section only) and `docs/` if a documented
  install path turns out wrong. No Go source files at all — if the release
  build exposes a Go bug, report it instead of fixing it; another branch owns
  every `.go` file.
- No new project dependencies. Installing the goreleaser *tool* locally
  (`go install`, a release binary, or a package manager) is fine — it is
  tooling, not a dependency.
- Do NOT create or push any git tag. Preparing the release is this task;
  cutting it is the maintainer's decision.

## Safety

No Minecraft instances, no API, no fixtures — this task should never touch
anything outside the worktree except the Go module cache. If any step wants
the network beyond downloading the goreleaser tool itself, stop and report
instead. When done, verify the real-instance jar counts are still 33
(`26.2-fabric-mod`) and 23 (`26.3-fabric-mod`) and report them; the point is
proving this task could not have touched them.

## Work

1. Read `.goreleaser.yaml`, `.github/workflows/release.yml`,
   `.github/workflows/ci.yml`, `Makefile`, `go.mod` (module path, Go
   version), and `README.md`'s install section.
2. Install goreleaser v2 locally and run `goreleaser check` (or `goreleaser
   check -q` for CI). Fix every finding: common ones are archive naming,
   missing `dist/` in `.gitignore`, nfpm globs matching nothing, and
   pre/post hooks that assume tools CI lacks.
3. Add a CI job that runs the check on every PR so the config cannot rot
   again. Keep it fast — `check` does not build.
4. Run `goreleaser release --snapshot --clean --skip=publish` (and
   `--skip=validate` only if you can justify why validation cannot run
   locally). Confirm real artifacts land in `dist/` for linux/darwin/windows
   on amd64 and arm64, archives contain `LICENSE`/`README.md` as configured,
   and at least the linux/amd64 binary runs `--help` and `version`
   successfully.
5. Confirm the `dist/` directory is gitignored and that no build output is
   left tracked or staged.
6. If `README.md` documents an install path (`go install …@latest`, deb/rpm,
   AUR, Homebrew) that the pipeline cannot actually produce, correct the docs
   rather than leaving a promise the release cannot keep.

## Verification

```
cd <worktree>
goreleaser check
git status --short          # only the files listed under Rules
```

Report the snapshot build matrix (which GOOS/GOARCH produced artifacts) and
the `--help`/`version` smoke-test output.

## Deliverable

Commit on your branch. Report: commit hash, files changed, every `check`
finding and what you changed because of it, the snapshot matrix, the smoke
test output, and an explicit go/no-go for tagging `v0.1.0` with anything
still missing.
