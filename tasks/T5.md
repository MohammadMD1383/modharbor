# Task T5 — `export` must use the app's Modrinth client (B7)

## Context

Every command that talks to Modrinth uses the client the app already built
(`a.MR()`), which carries the user's configured base URL, User-Agent and
cache. `export` is the exception: `internal/mrpack/export.go` calls
`config.Load("")` mid-command and constructs its own client, so a configured
base URL is silently ignored and config is re-read from disk halfway through.

Work in a git worktree branched from `main`:

```
git worktree add ../modharbor-t5 -b fix/export-client main
```

## Behaviour

- `internal/mrpack`: the export path accepts a `*modrinth.Client` parameter
  instead of building one. Match the style of `Install`, which already takes
  its client this way. `config.Load("")` must disappear from the export path.
- `internal/cli/mrpack.go`: the `export` command passes `a.MR()`.
- If the client parameter threads through an unexported helper, keep the
  change minimal — do not redesign the package.
- Behaviour is otherwise identical: same `.mrpack` bytes for the same input.
